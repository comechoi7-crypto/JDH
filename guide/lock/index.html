비밀번호로 잠그기

페이지의 한 부분은 누구나 보게 하고, 나머지는 비밀번호를 넣어야 보이게 하는 방법입니다. 11월 정단회 법위사정 공유 페이지의 회의록 원문 보기를 이 방식으로 만들었습니다.

원리직접 해 보기만드는 순서코드알아 둘 점내려받기

1어떤 원리인가요

가릴 부분을 흐리게만 만든 것이 아니라, 올리기 전에 내용 자체를 암호문으로 바꿔 넣습니다. 화면에 보이는 흐린 글자는 같은 길이의 임의 글자일 뿐이고, 비밀번호를 넣으면 그 자리에서 원문으로 풀립니다.

틀린 번호를 넣으면 '비밀번호가 맞지 않습니다'가 뜹니다. 한 번 맞게 넣으면 두 곳이 함께 풀립니다.

3만드는 순서

  1. 원본에 가릴 곳 표시원본.html에서 가릴 부분을 <priv> … </priv>로 감쌉니다.
  2. 비밀번호 정하기.pw 파일에 비밀번호 한 줄만 적습니다.
  3. 암호화 실행python build.py → 잠긴 index.html이 만들어집니다.
  4. 확인index.html을 열어 틀린 번호·맞는 번호를 넣어 봅니다.
  5. 올리기깃허브에는 index.html만 올립니다.

파일 구성

파일역할올리기
원본.html원문 전체, 가릴 곳 표시✕
build.py<priv> 부분을 암호화✕

원문과 비밀번호가 든 파일은 내 컴퓨터에만 두고, 암호화된 결과만 공개하는 것이 핵심입니다.

4코드

① 원본에 가릴 곳 표시

<p>이 부분은 누구나 봅니다.</p>
<priv>
  <p>이 부분은 잠깁니다.</p>
</priv>

<priv>는 여러 곳에 써도 됩니다. 안에 또 <priv>를 넣지는 마세요.

② 암호화 프로그램 (build.py)

"""부분 잠금 페이지 만들기
같은 폴더의 원본.html 을 읽어 <priv>…</priv> 부분을 .pw 의 비밀번호로 암호화하고
index.html 을 만듭니다.  깃허브에는 index.html 만 올립니다.

처음 한 번:  pip install cryptography
실행:        python build.py
"""
import base64, os, re, random
from pathlib import Path
from cryptography.hazmat.primitives.ciphers.aead import AESGCM
from cryptography.hazmat.primitives.kdf.pbkdf2 import PBKDF2HMAC
from cryptography.hazmat.primitives import hashes

HERE = Path(__file__).resolve().parent
PW   = (HERE / ".pw").read_text(encoding="utf-8").strip()      # ① 비밀번호 읽기
SALT = os.urandom(16)                                          # ② 임의값(공개돼도 됨)
KEY  = PBKDF2HMAC(algorithm=hashes.SHA256(), length=32,        # ③ 비밀번호 → 열쇠
                  salt=SALT, iterations=300000).derive(PW.encode())
b64  = lambda x: base64.b64encode(x).decode()

def lock(m):                                                   # ④ <priv> 한 덩어리 잠금
    inner = m.group(1)
    iv = os.urandom(12)
    ct = AESGCM(KEY).encrypt(iv, inner.encode(), None)
    plain = re.sub(r"<[^>]+>|\s+", "", inner)
    fake = "".join(chr(0xAC00 + random.randrange(11172)) if random.random() > .15 else " "
                   for _ in range(max(30, len(plain))))
    return (f'<div class="lock" data-iv="{b64(iv)}" data-ct="{b64(ct)}">'
            f'<div class="fog" aria-hidden="true">{fake}</div>'
            f'<button type="button" class="unlock">🔒 비밀번호 입력</button></div>')

src = (HERE / "원본.html").read_text(encoding="utf-8")
src = re.sub(r"<!--.*?-->", "", src, flags=re.S)              # 주석 제거(주석 속 <priv> 오인 방지)
n   = len(re.findall(r"<priv>", src))
out = re.sub(r"<priv>(.*?)</priv>", lock, src, flags=re.S)     # ⑤ 모든 <priv> 교체
out = out.replace("{{SALT}}", b64(SALT))                       # ⑥ 임의값 심기
(HERE / "index.html").write_text(out, encoding="utf-8")
print(f"완료: index.html (잠근 부분 {n}곳)")

# 안전 점검: 비밀번호가 결과에 들어갔는지
if PW in out:
    print("⚠ 경고: 결과 파일에 비밀번호 문자열이 보입니다. 올리기 전에 확인하세요.")
  • ①~③ 비밀번호를 30만 번 섞어 열쇠를 만듭니다. 하나씩 넣어 보는 시도를 느리게 하려는 것입니다.
  • ④ 원문을 AES-GCM으로 암호화해 data-ct에 넣고, 화면에는 같은 길이의 임의 한글만 흐리게 둡니다.
  • ⑤ 원본의 <priv>를 모두 찾아 잠긴 덩어리로 바꿉니다.
  • ⑥ 임의값(SALT)을 페이지에 넣습니다. 이 값은 공개되어도 괜찮습니다.

③ 잠금 해제 코드 (원본.html 맨 아래)

const SALT="{{SALT}}";   // build.py가 실제 값으로 바꿔 넣음
const b=s=>Uint8Array.from(atob(s),c=>c.charCodeAt(0));
async function unlock(pw){
  const km=await crypto.subtle.importKey('raw',
    new TextEncoder().encode(pw),'PBKDF2',false,['deriveKey']);
  const key=await crypto.subtle.deriveKey(
    {name:'PBKDF2',salt:b(SALT),iterations:300000,hash:'SHA-256'},
    km,{name:'AES-GCM',length:256},false,['decrypt']);
  for(const l of document.querySelectorAll('.lock')){
    const pt=await crypto.subtle.decrypt(
      {name:'AES-GCM',iv:b(l.dataset.iv)},key,b(l.dataset.ct));
    const d=document.createElement('div');
    d.innerHTML=new TextDecoder().decode(pt);
    l.replaceWith(...d.childNodes);   // 흐린 글자 → 원문
  }
}

④ 설정 맞추기 — 중요

파이썬(build.py)과 자바스크립트(원본.html)의 설정이 하나라도 다르면, 맞는 비밀번호로도 풀리지 않습니다.

항목값
열쇠 만드는 방식PBKDF2 + SHA-256
반복 횟수300000
암호화 방식AES-GCM 256

⑤ 실행

pip install cryptography   # 처음 한 번만
python build.py            # 맥은 python3 build.py

'완료: index.html (잠근 부분 ○곳)'이 나오면 성공입니다.

5알아 둘 점

  • 고칠 때 — index.html을 직접 고치지 말고, 원본.html을 고친 뒤 build.py를 다시 실행합니다.
  • 공개 범위 — 링크를 받은 사람은 누구나 공개 부분을 볼 수 있습니다.
  • 잠금 수준 — 숫자 네 자리는 시간을 들여 하나씩 넣어 보면 풀립니다. '지나가다 보는 것을 막는 정도'로 보시고, 더 단단히 하려면 비밀번호를 길게 정하세요.
  • 수정 기록 — 잠그기 전의 원문을 한 번이라도 깃허브에 올렸다면 수정 기록에 남아 있습니다.
